## 2. 已与老师确认的业务定义

| 项目 | 已确认结论 |
| --- | --- |
| 接近 A/B | A、B 是两个不同增益下的接近值，用于降低单增益测量不准的风险；返回共 4 字节 |
| 多光谱自动模式 | 周期历史记录携带实际增益，记录长度 22 字节 |
| 多光谱手动模式 | `0x42` 已指定增益，`0x43` 只返回 20 字节光谱值，不带增益 |
| 多光谱、紫外周期 | 1 分钟一次 |
| FIFO、接近周期 | 10 分钟一次 |
| 加速度周期 | 1 秒一次 |
| 历史范围 | 累计一天的数据后上传 |
| 上传类型 | 一次只上传一种传感器数据 |

### 2.1 `0x49` 接近数据格式（已确认）

Word 协议存在矛盾：

```text
数据格式章节：接近 A(uint16) + 接近 B(uint16) = 4 字节
0x49 命令章节：接近数据 = 2 字节
```

最终按 4 字节实现：

```text
AA 49 A_L A_H B_L B_H XOR BB
```

当前 A/B 增益实现：

```text
A：使用 APP 命令指定的低 2 位增益
B：固定使用 GAIN=3，即 8x 增益
```

A/B 代表两个增益下的接近原始值，用于相互补充、避免单一增益下测量不准。若
后续要求两个固定增益而不是由 APP 指定 A，还需要确认具体档位。

### 2.2 `0x50` 的上传行为（已确认）

目标行为：

```text
APP 发送一次 0x50
  -> TYPE 指定一种传感器
  -> 设备自动分包上传该传感器累计一天的历史
  -> 直到该类型的本地历史全部传完
  -> 不混装其他传感器，也不持续实时推送新采集数据
```

当前固件只有单帧最小版本，尚未实现“一天数据连续多包发送”。

### 2.3 `0x51` 的多包格式如何定义

Word 协议描述了“自动上报多包直到本地数据上传完毕”，但没有定义：

- 每包最多包含几组记录；
- 数据类型 TYPE；
- 包序号 SEQ；
- 总包数 TOTAL；
- 本包记录数 COUNT；
- 有效数据长度 LEN；
- 最后一包/上传结束标志；
- 是否需要 APP 确认和失败重传。

当前 `0x51` 格式只有：

```text
AA 51 第一组时间戳(4) 记录1 记录2 ... XOR BB
```

当前响应没有 TYPE。APP 必须记住刚才请求的是哪种传感器，并且一次只能顺序请求
一种数据。（所以一次只能传输一个传感器数据）

确认是否允许扩展为类似：

```text
AA 51 TYPE SEQ TOTAL COUNT TIMESTAMP PAYLOAD XOR BB
```

### 2.4 传感器采样周期（已确认）

| 传感器         | 采样周期 | 上传周期 | 是否实时 | 是否允许批量 |
| -------------- | -------- | -------- | -------- | ------------ |
| AS7341 多光谱  | 60 秒    | 累计一天后由 `0x50` 请求 | 否 | 是 |
| AS7341 FIFO    | 600 秒   | 累计一天后由 `0x50` 请求 | 否 | 是 |
| AS7331 紫外    | 60 秒    | 累计一天后由 `0x50` 请求 | 否 | 是 |
| WH4530A 接近   | 600 秒   | 累计一天后由 `0x50` 请求 | 否 | 是 |
| ADXL345 加速度 | 1 秒     | 累计一天后由 `0x50` 请求 | 否 | 是 |

当前 `0x4E` 的 X 是 1 字节。若最小周期取 1 秒，则 FIFO/接近需要 X=600，超过
1 字节上限 255。需要把 X 扩展为 2 字节，或者直接发送各传感器的周期秒数。

### 2.5 一天历史的存储需求（保存时长已确认）

当前全部历史位于 RAM：

| 数据类型 | 当前最多保存 | 每组长度 |
| -------- | -----------: | -------: |
| 多光谱   |        12 组 |  22 字节 |
| FIFO     |         1 组 | 256 字节 |
| 紫外     |        20 组 |   8 字节 |
| 接近     |        20 组 |   4 字节 |
| 加速度   |        20 组 |   6 字节 |

当前行为：

- 缓存满后覆盖最旧数据；
- 复位或断电后全部丢失；
- 新的 `0x4E` 会清空全部历史；
- `0x51` 成功加入发送队列后就清空对应历史；
- APP 尚未发送业务确认，断线时可能无法重传。

按已确认周期，一天的数据量为：

| 数据类型 | 每天组数 | 一天原始数据 |
| --- | ---: | ---: |
| 多光谱 | 1440 | 31680 字节 |
| FIFO | 144 | 36864 字节 |
| 紫外 | 1440 | 11520 字节 |
| 接近 | 144 | 576 字节 |
| 加速度 | 86400 | 518400 字节 |
| **合计** | **89568** | **599040 字节（约 585 KiB）** |

若每组都另存 4 字节时间戳，约需 935 KiB。当前历史 RAM 只有约 1.2 KiB，不能
保存一天数据；必须确认使用外部 Flash、内部 Flash 分区，还是压缩/降低加速度
数据量。断电后是否要求保留一天历史仍需确认。

### 2.6 数据最终需要什么单位和校准方式

目前主要完成了“读到原始值并上传”，还需要确认最终业务含义：

| 数据     | 待确认内容                                             |
| -------- | ------------------------------------------------------ |
| 多光谱   | 22 字节是否最终确定；F1～F8/Clear/NIR 是否需要校准系数 |
| 紫外     | 上传原始计数还是实际辐照度；UVA/UVB/UVC 的单位和缩放   |
| 紫外温度 | 字段单位、符号和缩放方式                               |
| 接近     | 原始 PS 计数还是换算为实际距离                         |
| 加速度   | 原始 ADC、mg 还是 g；量程和采样率                      |
| FIFO     | 上传原始波形，还是设备/APP计算闪烁频率                 |

没有确定单位、量程和校准方法，APP虽然能显示数字，但无法判断数据是否准确。

### 2.7 默认传感器参数是否可以确定

当前默认值（原始工程参数）：

```text
AS7341：ATIME=29，ASTEP=599，AGAIN=10
FIFO：FD_TIME=720，GAIN=5
AS7331：GAIN=9，即 512x
接近：GAIN=0，即 1x
```

需要确认这些值是：

- 正式业务参数；
- 只用于当前测试；
- 还是需要由 APP 每次连接后配置。

### 2.8 时间戳如何定义

当前实现：

- `0x4E` 中 4 字节时间戳直接设置 BK3633 软件时钟；
- 单位按 Unix 秒处理；
- `0x51` 只携带第一组记录时间戳；
- 后续记录时间按采集周期推算；
- 历史上传期间错过的采集不会补采。
